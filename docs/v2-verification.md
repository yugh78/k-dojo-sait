# K-Dojo v2 — отчёт о проверках

## Docker — обновление 25.09.2026

Текущая конфигурация называется `compose.yml`; команды ниже приведены с этим именем по умолчанию. При переименовании сохранены имя проекта `kdojo-v2` и все volumes. Старый `docker-compose.yml` удалён из рабочей папки и доступен в истории Git.

Docker Desktop Engine успешно запущен. `docker compose build` собрал Django и Nuxt; `safe_migrate` и `seed_club` выполнены на новой PostgreSQL в отдельном volume. Все четыре сервиса запущены, healthcheck БД/backend/frontend проходят.

Через `https://localhost` проверены `/`, `/schedule/`, `/pricing/`, `/api/health/`, `/api/programs/`, `/admin/login/`, `/static/admin/css/base.css`, `/sitemap.xml`: HTTP 200, health API возвращает `{"status": "ok"}`. При HTTP-проверке использовался `curl -k`, поскольку локальному центру сертификатов Caddy ещё не предоставлено доверие в Windows. Публичный сертификат на реальном домене не проверялся.

`docker compose run --rm -e DJANGO_DEBUG=true backend python manage.py test club myapp`: 17 тестов пройдены, временная тестовая БД удалена. Первый запуск без тестовой настройки DEBUG завершился ошибками из-за HTTPS-редиректов; работающие сервисы остаются с `DJANGO_DEBUG=false`.

Повторный запуск: `scripts/docker-up.ps1`. Документация ниже сохраняет результаты и ограничения проверки от 17.09.2026.

Состояние на 17.09.2026. Рабочая ветка: `kdojo-v2`. Исходный `master`: `4cf5e309bed3238e97c34bf2a2ea42f3679401ad`.

## Реализовано

- Nuxt SSR: главная, клуб, три направления и маршрут для новых дисциплин, тренеры и их страницы, расписание, цены, события и детали, результаты, галерея, контакты, юридические страницы, 404.
- Контент приходит из Django REST API и редактируется через Admin. Внесены подтверждённые факты ТЗ: 3 направления, 3 тренера, 24 занятия недели, 5 тарифов и семейные льготы. Seed не перезаписывает правки администратора.
- Форма сохраняет заявку в БД, проверяет телефон, возраст, согласие, CSRF и honeypot; действует ограничение частоты. Сохраняются источник, UTM, текст и время согласия. Ошибка необязательного уведомления не отменяет запись.
- Старые таблицы Product/Request и миграции 0001–0003 сохранены. Новая миграция расширяет Request. `safe_migrate` отказывается применять историческую разрушительную 0003 к непустой старой схеме.
- Отдельные Compose project и volumes v2, Caddy, Dockerfiles, healthchecks, фиксированные зависимости, CI, инструкции эксплуатации и проверок.

## Изоляция и сохранность

PostgreSQL проверялся в новом каталоге `.tools/postgres-checks/run-xgylkeex`, только на `127.0.0.1:15432`. После проверки экземпляр остановлен; синтетические данные и dump оставлены. Скрипт `scripts/check_postgres.py` при каждом запуске создаёт отдельный кластер. E2E и Lighthouse также используют отдельные уникальные SQLite; рабочая development-БД не очищается.

Исходная Docker-конфигурация, старые миграции и `master` не изменены. Старые заявки и Docker volumes не удалялись. Корневой `node_modules` убран только из индекса Git; локальные файлы оставлены. `git push` не выполнялся.

## Что ещё требует реального окружения и данных владельца

- Docker Engine/WSL на этой машине отсутствуют. Выполнена проверка конфигурации Compose и native PostgreSQL/Caddy; контейнерная сборка, запуск всего Compose и выдача HTTPS-сертификата на реальном домене пока не проверены. CI настроен, но удалённый запуск не выполнялся.
- Реальное наличие и состояние прежних volumes/БД остаются неизвестными. Успешное восстановление синтетической БД не заменяет инвентаризацию и репетицию миграции реальных заявок по `docs/v2-migration-plan.md`.
- `check --deploy` оставляет только W021: домен не включён в HSTS preload list. Решение требует проверки реального домена и всех поддоменов.
- Нужны фотографии, биографии и регалии, сертификат «Маугли», недостающие адреса, события/результаты, экипировка и юридические тексты. Полный список есть в README. Неподтверждённые данные не выдуманы.
- Production-форма начнёт принимать заявки после заполнения privacy_text/consent_text и включения legal_ready в SiteSettings. Локальный DEBUG-режим позволяет проверить форму на тестовых данных.
- Реальная доставка Telegram не проверялась: ключи не предоставлены. Автотест проверил, что сбой уведомления не теряет заявку.
