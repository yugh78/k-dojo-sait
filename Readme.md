# K-Dojo

Сайт спортивного клуба K-Dojo на Nuxt 4, Vue 3 и TypeScript. Весь код сайта находится в `frontend/`, контент хранится в локальном JSON. Запись на тренировку доступна по телефону и через Telegram.

## Быстрый старт

В Windows выполните из корня проекта одну команду:

```powershell
.\start.cmd
```

Скрипт сам подключает локальные Node.js и pnpm из `.tools/`, при необходимости устанавливает зависимости и запускает сайт. Настраивать PATH или менять политику PowerShell не нужно. Остановка — `Ctrl+C`.

В новом клоне репозитория нужны Node.js 24 и pnpm 10.32.1 либо Corepack: локальные инструменты из `.tools/` не хранятся в Git.

Для запуска вручную или в другой ОС:

Из корня репозитория:

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm dev
```

Сайт доступен по адресу http://localhost:3000. Для локального запуска переменные окружения не нужны.

## Структура сайта

| Путь | Назначение |
| --- | --- |
| `frontend/app/app.vue` | Общая оболочка сайта |
| `frontend/app/pages/` | Страницы и маршруты |
| `frontend/app/components/` | Компоненты интерфейса |
| `frontend/app/assets/main.css` | Общие стили |
| `frontend/app/data/club.json` | Направления, тренеры, расписание, цены, FAQ и контакты |
| `frontend/content/gallery/` | Категории, альбомы, подписи и избранные фотографии |
| `frontend/scripts/prepare-gallery.mjs` | Проверка данных галереи, подготовка WebP и порций фотографий |
| `frontend/app/composables/useClubContent.ts` | Чтение и фильтрация локального контента |
| `frontend/public/` | Изображения и другие статические файлы |
| `frontend/server/routes/` | Генерация `robots.txt` и `sitemap.xml` |
| `frontend/tests/` | Модульные и браузерные тесты |

Контент редактируется в `club.json`. Файл из `frontend/public/` доступен по пути от корня сайта: например, `public/brand/k-dojo.svg` — по адресу `/brand/k-dojo.svg`. После изменения контента или кода опубликованный сайт нужно пересобрать.

### Расписание и запись

Единый источник — массив `schedule` в `frontend/app/data/club.json`. Он используется в кратком блоке на главной, модальном окне и на `/schedule`. Параллельные занятия остаются отдельными записями с уникальными `id`; время и тренеры не объединяются.

«Все дни и группы» открывает окно с текущим днём по московскому времени. Направление, возраст и тренер фильтруются совместно через общую функцию `filterSchedule` и компонент `ScheduleFilters`. Для возраста 3–7 лет включительно показывается только Маугли; остальные фильтры продолжают действовать.

Кнопка «Записаться» в окне показывает существующий `ApplicationForm` с выбранными направлением, днём, временем, возрастной группой и тренерами. Возврат к расписанию сохраняет фильтры и положение списка. На отдельной странице выбранное занятие передаётся тем же компонентом через `session` в ссылке на контакты.

Запись по-прежнему согласуется с клубом по телефону или в Telegram. Компонент показывает готовое сообщение и кнопку копирования; ссылка Telegram передаёт [черновик сообщения](https://core.telegram.org/api/links#public-username-links), если в чате разрешено писать. Сайт не отправляет заявку автоматически.

### Галерея

Структура: `/gallery` → `/gallery/категория` → `/gallery/категория/альбом`. Все данные редактируются в `frontend/content/gallery/`; компоненты менять не требуется.

- `catalog.json`: массив `categories` задаёт названия, описания и порядок категорий; `albums` — метаданные и порядок альбомов; `featured` — до четырёх избранных фотографий на главной в нужном порядке.
- `albums/<slug>.json`: массив фотографий одного альбома. Порядок элементов определяет порядок просмотра. `id` должен быть уникальным положительным числом внутри альбома.
- Оригиналы лежат в `frontend/public/gallery/` и разложены по разделам. Имена папок пишутся строчными буквами; регистр имён самих файлов сохраняется.

```text
frontend/public/gallery/
├── kyokushin/
│   ├── children/      # Каратэ — дети и подростки
│   └── adults/        # Каратэ — взрослые
├── bjj/               # BJJ и грэпплинг
├── mowgli/            # Маугли
├── competitions/      # Соревнования
├── camps/             # Спортивные сборы
└── club/              # Жизнь клуба
```

Внутри раздела можно создавать подпапки альбомов. Например, фото детской тренировки доступно как `/gallery/kyokushin/children/IMG_1051.JPG`. Добавьте этот путь в `src` соответствующего JSON-альбома. Папки организуют оригиналы; категории, альбомы и подборка на сайте по-прежнему задаются в `content/gallery/`. Одна фотография может использоваться в разных подборках без копирования файла. Пустые разделы содержат `.gitkeep`, чтобы папки сохранялись в Git.

Чтобы добавить альбом, внесите запись в `catalog.json`:

```json
{
  "slug": "summer-camp",
  "category": "camps",
  "title": "Летние сборы",
  "date": "2026-07-15",
  "description": "Тренировки и время вместе.",
  "cover": 1
}
```

И создайте `albums/summer-camp.json`:

```json
[
  {
    "id": 1,
    "src": "/gallery/camps/summer-camp/camp-01.jpg",
    "caption": "Работа в парах",
    "position": "center 60%"
  }
]
```

`cover` — ID фотографии этого альбома. Необязательное `coverPosition` (например, `"center 25%"`) настраивает кадрирование обложки отдельно от фотографии в сетке. `date` содержит реальную дату в формате `YYYY-MM-DD`; если она неизвестна, укажите `null`. Даты двух исходных подборок взяты из EXIF фотографий. Для новой категории добавьте объект со `slug`, `title` и `description` в `categories`. Пустые категории показывают сообщение без вымышленных альбомов.

Запись `{"album": "summer-camp", "photo": 1}` в `featured` добавляет фотографию на главную. Просмотр из избранной подборки переключает фотографии только внутри альбома выбранного кадра.

При `start.cmd`, `pnpm dev` и `pnpm build` автоматически запускается подготовка галереи. Она проверяет ссылки и обложки, учитывает ориентацию EXIF, создаёт WebP шириной до 240, 480, 960, 1600 и 2400 пикселей и разбивает метаданные на порции по 24 кадра. Неизменившиеся фото берутся из кеша. После изменения данных перезапустите разработческий сервер; опубликованный сайт пересоберите. Отдельно запустить подготовку можно командой `pnpm gallery:prepare` из `frontend/`.

Результат хранится в игнорируемом `.gallery-cache/`. Изображения получают имена с хешем содержимого и длительное кеширование; JSON-порции включаются в серверную сборку. В клиентский JS общий архив фотографий не попадает. Страница загружает по 24 фотографии, Lightbox хранит до пяти порций метаданных, показывает до девяти миниатюр и предзагружает два соседних изображения. Эти ограничения сохраняются при увеличении альбома до тысяч фотографий.

Просмотрщик поддерживает стрелки, клавиатуру, горизонтальные свайпы, миниатюры, `Esc` и клик снаружи. Анимации учитывают настройку уменьшения движения. Для видео можно добавить к фотографии поле `video` с локальным путём MP4/WebM: `src` будет обложкой, воспроизведение запускается пользователем.

Подготовка изображений использует [Sharp](https://sharp.pixelplumbing.com/api-resize/), а выдача порций — [server assets Nitro](https://v2.nitro.build/guide/assets).

## Команды

Все команды ниже выполняются из папки `frontend`.

| Команда | Действие |
| --- | --- |
| `pnpm dev` | Запустить сайт для разработки |
| `pnpm check` | Проверить ESLint, форматирование, TypeScript и модульные тесты |
| `pnpm format` | Отформатировать файлы |
| `pnpm test` | Запустить модульные тесты |
| `pnpm build` | Собрать production-версию в `.output/` |
| `pnpm preview` | Локально посмотреть готовую сборку |
| `pnpm test:e2e` | Проверить готовую сборку в браузере |

Перед первым запуском браузерных тестов установите Chromium:

```sh
pnpm exec playwright install chromium
pnpm build
pnpm test:e2e
```

Playwright сам запускает собранный сайт. В GitHub Actions при push и pull request выполняются основные проверки, сборка и браузерные тесты.

## Публикация

Сайт использует серверный рендеринг Nuxt. Для текущей сборки нужен хостинг с Node.js 24.

1. Установите зависимости и выполните `pnpm build` в `frontend/`.
2. Задайте `NUXT_PUBLIC_SITE_URL` — полный публичный адрес сайта, например `https://example.com`, без завершающего `/`. Он используется для SEO-ссылок, `robots.txt` и `sitemap.xml`.
3. Из `frontend/` запустите:

```sh
node .output/server/index.mjs
```

При необходимости задайте `PORT` и `HOST` в окружении процесса. Для переноса готовой сборки используйте весь каталог `.output/`.

## Локальный архив

`backups/legacy-server/` содержит сохранённую старую базу. Этот каталог исключён из Git и не нужен для работы сайта. Старый корневой `.env` не используется. `.tools/` содержит локальные инструменты для `start.cmd`; при установленных Node.js и pnpm этот каталог не требуется.
